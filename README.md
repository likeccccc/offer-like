# OFFER Like · 招聘表单填写助手

**把重复填写简历的时间，留给寻找合适的机会。**

OFFER Like 是一款浏览器扩展：将简历整理为可复用的个人资料库，在招聘网页中自动识别并填写表单；遇到漏填项，还可以用「辅助填充」按字段补上，减少来回复制、粘贴。

[下载安装](#下载安装) · [开始使用](#开始使用) · [辅助填充](#辅助填充) · [数据与隐私](#数据与隐私) · [反馈问题](https://github.com/likeccccc/offer-like/issues)

> 当前为试用版本，主要使用 Edge 进行人工验证。不同网站的控件和经历结构存在差异，自动填写可能遗漏或匹配不准确，请在提交申请前核对结果。

## 可以帮你做什么

| 功能 | 使用方式 |
| --- | --- |
| 个人资料库 | 集中维护个人信息、求职意向，以及教育、工作、实习、项目、校园、奖项、证书、语言、论文等资料 |
| 简历解析 | 导入 DOCX、文字型 PDF、TXT、Markdown，或粘贴简历文本，通过 AI 提取结构化资料 |
| 一键填充 | 扫描当前页面字段，结合本地规则与 AI 映射填写资料，并尝试按经历数量添加空白条目 |
| 辅助填充 | 先点网页输入框，再点「姓名」「公司名称」等资料按钮，逐项补填 |
| 字段定位提示 | 点击网页字段时，辅助面板尝试定位对应按钮，并以浅红色标记 |
| 多段经历 | 资料按条目保存，辅助面板可以分别选择某一段经历的学校、公司、部门或描述 |
| 证件照 | 在个人信息卡保存不超过 300 KB 的 JPG / PNG，填充时尝试交给网页上传控件 |
| AI 服务配置 | 提供 DeepSeek、千问、Kimi、豆包和自定义 OpenAI 兼容接口的配置入口 |

## 下载安装

无需安装 Node.js 或运行构建命令，可直接加载源码目录。

1. 在仓库首页选择 **Code → Download ZIP**，或[下载 main 分支源码](https://github.com/likeccccc/offer-like/archive/refs/heads/main.zip)。
2. 解压到一个长期保留的文件夹。
3. 在 Edge 地址栏输入 `edge://extensions`，打开「开发者模式」。
4. 点击「加载解压缩的扩展」，选择**直接包含 `manifest.json` 的文件夹**。
5. 在浏览器扩展菜单中找到 OFFER Like，打开「档案盒」开始配置。

Chrome 可通过 `chrome://extensions` 加载，实际兼容性需自行验证。请勿直接选择 ZIP 文件或解压目录的上一级。

**更新时：**将新代码放到原加载目录，在扩展管理页点击重新加载，再刷新已打开的招聘网页。普通更新无需卸载扩展；卸载可能导致本地资料丢失。

## 开始使用

### 1. 配置 AI

在扩展弹窗或资料库中打开「AI 配置」，依次填写：

| 配置项 | 填写说明 |
| --- | --- |
| AI 服务商 | 选择正在使用的服务商，或选择自定义兼容接口 |
| API Key | 填入该服务商签发的 Key，不要写进源码 |
| 接口地址 | 使用服务商提供的兼容接口基础地址；扩展会拼接 `/chat/completions` |
| 模型名称 | 使用当前账号可调用的准确模型标识，必须与接口服务商匹配 |

点击「保存」和「测试连接」。服务商预设在 [shared/ai-config.js](shared/ai-config.js) 中定义；模型是否可用取决于你的账号权限及服务商配置。自定义地址还可能受到浏览器网络、跨域和扩展权限限制。

AI 请求使用你自己的账户，费用由所选服务商收取。手动录入资料后，**辅助填充不需要调用 AI**。

### 2. 整理个人资料

打开档案盒，导入简历或粘贴文本解析，也可以直接手动录入。解析后核对姓名、联系方式、日期，以及每段经历是否完整、是否被正确拆分。

建议将学校、公司和奖项分别保存为独立条目。最高学历、籍贯、毕业时间等容易漏填的资料，也应在资料库中确认。

文件导入注意事项：

- PDF 需要包含可提取的文字，扫描图片型 PDF 暂无 OCR 识别。
- 旧版 `.doc` 请先另存为 `.docx`，当前解析器按 DOCX 结构读取。
- 证件照在**个人信息卡**中选择，支持 JPG / PNG，文件最大 **300 KB**；超限时请先自行压缩。

### 3. 在招聘网页填写

打开简历编辑页面，点击右下角 OFFER Like 悬浮按钮，再点击「一键填充本页」。

```text
维护资料 → 扫描页面 → 按需添加经历条目 → 匹配并填写 → 核对结果
```

程序会尝试操作文本框、下拉框、单选、日期和地区控件。多段经历需要网页有可识别的条目结构及添加入口，实际展开数量和填写结果应由你确认。

## 辅助填充

适合补填遗漏字段，或在不使用 AI 的情况下逐项填写。

1. 打开悬浮面板，点击「辅助填充」。
2. 用鼠标点一下招聘网页中要填写的输入框。
3. 在辅助面板中选择对应资料按钮，例如「公司名称」。
4. 有多段经历时，先确认按钮位于正确的条目下，再点击填入。

例如，要补填第二段实习的部门名称：先点网页里对应的部门输入框，再到「实习经历 · 第 2 条」中点击「部门名称」。

按钮仅显示字段名称，不直接展开个人信息值。面板会尝试自动定位与当前输入框匹配的按钮，并以浅红色提示；匹配不准确时，可以自行选择其他按钮。

辅助填充同样受网页控件限制。对于必须选择候选项的下拉框，请确认内容已经选中，而不只是显示在搜索框里。

## 数据与隐私

**个人资料、简历文本、证件照和 API Key 保存在当前浏览器的扩展本地存储中。** 它们不属于仓库源码，也不会因为安装或更新代码而自动上传到 GitHub。

| 操作 | 数据去向 |
| --- | --- |
| 保存资料与配置 | 当前浏览器的 `chrome.storage.local` |
| AI 解析简历 | 简历文本发送至你配置的 AI 接口 |
| AI 字段匹配 | 根据请求路径，发送网页字段信息、属性定义或相关简历内容至所配置接口 |
| 自动或辅助填写 | 所选资料写入当前招聘网页，之后由该网站处理 |
| 证件照填写 | 图片交给招聘网页的文件控件，网站可能立即发起上传 |

本地存储不等于加密保险箱，也不代表所有操作都离线完成。AI Key 会用于向所配置服务商认证；请只填写你信任的接口地址。

扩展当前使用以下权限：

- **storage**：保存资料、照片及配置。
- **网页内容脚本**：在普通网页中显示悬浮入口、扫描和操作表单。
- **AI 服务地址访问权限**：向配置的服务接口发送请求。
- **debugger**：在普通点击无法触发控件时，尝试浏览器级点击；使用时浏览器可能显示调试提示。

反馈问题时请先遮挡个人信息。调试日志可能包含字段值，不要直接公开完整日志、简历、照片或 API Key。仓库已通过 `.gitignore` 排除本地备份、内部交接文档、日志及 `.env` 文件。

## 常见问题

### 为什么有的字段没有填上？

先检查资料库是否有对应内容，再确认网页是否已经展开该段经历。自定义下拉、联动地区、日期选择器或缺少标签的字段可能无法正确识别，可使用辅助填充或手动补全。

### 为什么输入了公司或学校，最后又变成空白？

某些控件只接受从候选列表中选中的值。输入文字只是搜索，尚未完成选择。请检查是否出现候选项，并手动选中；如果能稳定复现，欢迎反馈控件表现。

### 为什么照片交付成功，但网页仍然没有头像？

将文件交给控件与服务器上传完成是两个步骤。网站还可能要求裁剪、确认，或限制图片尺寸、比例和格式。请查看网页上传提示，必要时手动上传。

### 测试连接提示 `model_not_found` / HTTP 404？

核对接口地址和模型名称是否属于同一个服务商，并确认账号有调用权限。例如，切换到千问接口后，不能继续使用 DeepSeek 的 `deepseek-chat` 模型标识。

### 为什么填写仍然比较慢？

耗时包括 AI 响应、网页渲染、经历展开，以及下拉和日期控件的交互等待。更换模型只会影响其中的 AI 部分。少量漏填项可用辅助填充处理，避免重新执行整页填写。

### 为什么更新后没有变化？

确认扩展加载的是新代码所在目录，重新加载扩展，并刷新招聘网页。已经打开的网页可能仍在运行旧内容脚本。

## 开发与验证

项目使用 Manifest V3、原生 JavaScript、HTML 和 CSS，没有独立业务后端，也无需 npm 构建。DOCX 和 PDF 解析所需的 JSZip、PDF.js 已放在 `vendor/` 中。

```text
offer-like/
├── manifest.json          # 扩展入口与权限
├── background.js          # 后台消息、AI 请求与浏览器点击
├── content/
│   ├── content.js         # 扫描、经历展开、自动与辅助填充
│   ├── content.css        # 悬浮入口和面板样式
│   └── inject.js          # 页面主环境中的控件交互
├── options/               # 个人资料库
├── popup/                 # 扩展工具栏弹窗
├── shared/                # AI 配置与资料字段定义
├── assets/                # 品牌图片
├── icons/                 # 扩展图标
├── vendor/                # 随附第三方库
└── tests/                 # Node.js 模拟回归用例
```

安装 Node.js 后，在项目根目录运行对应检查，例如：

```sh
node --check content/content.js
node tests/ai-config.cjs
node tests/assist-match.cjs
node tests/select-commit.cjs
node tests/portrait-upload.cjs
```

这些用例检查部分逻辑和模拟控件行为，不能替代真实招聘页面的人工验收。修改交互逻辑后，仍需在浏览器中验证展开、选中、失焦后的值以及上传结果。
